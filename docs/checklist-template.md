## Jellyfin (port 8096)

> For Jellyfin HDHR testing, treat manual add via `http://{host}:5004` as the required path.
> HDHR auto-detect is best effort only and may fail in bridge-network or NAT-like topologies even when manual setup works.

### Setup -- M3U Mode
- [ ] Add M3Undle as Live TV tuner via M3U URL -- `http://{host}:8080/m3u/m3undle.m3u`
- [ ] Add XMLTV guide source -- `http://{host}:8080/xmltv/m3undle.xml`
- [ ] Channel scan completes -- all published channels appear
- [ ] Channels appear in guide-number order (globally sorted, not insertion order)
- [ ] Guide data loads -- programme entries visible in TV Guide
- [ ] Live TV plays via M3U tuner (channel selected from guide)
- [ ] Channel switching works without stale stream
- [ ] Stream recovers after brief M3Undle restart

### Setup -- HDHR Mode
- [ ] Add M3Undle as Live TV tuner via HDHR manual URL -- `http://{host}:5004`
- [ ] Optional best-effort check: Jellyfin "Detect My Devices" finds the tuner in this topology
- [ ] Channel scan completes -- all published channels appear
- [ ] Channels appear in guide-number order
- [ ] Guide data loads -- programme entries visible
- [ ] Live TV plays via HDHR tuner (channel selected from guide)
- [ ] Channel switching works without stale stream
- [ ] HDHR playback is handled as direct play in Jellyfin (not a transcode session)
- [ ] Stream recovers after brief M3Undle restart

### HLS (Browser / Web UI)
- [ ] Start playback in Jellyfin web UI (browser) -- confirm session appears in `/status/streams`

### Channel Overrides
- [ ] Custom guide number appears correctly in Jellyfin channel list

### EPG
- [ ] Guide shows correct programme data aligned with channels
- [ ] Guide refreshes after M3Undle snapshot rebuild (no stale data)

### Xtream (if Jellyfin plugin available)
- [ ] TiviMate-style Xtream connection (`player_api.php`) tested -- playlist loads, stream plays

## Cross-Client Checks

### Stream Sharing
- [ ] An M3U-mode client and an HDHR-mode client can both watch the same channel concurrently

### Provider Stream Cap
- [ ] With provider `max-streams=2`, a third distinct-channel playback attempt fails predictably in the client

### Profile Switching
- [ ] Switch active profile while clients have a channel list loaded -- clients see new lineup on next channel scan/refresh
- [ ] In-progress streams on the old profile are not abruptly terminated (graceful handoff or natural timeout)

### CORS
- [ ] Jellyfin web UI (browser) can play streams cross-origin without CORS errors in browser console
